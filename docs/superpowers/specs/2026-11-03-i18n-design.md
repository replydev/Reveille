# Reveille internationalization — design

Date: 2026-11-03 · Branch: `replydev/i18`

## Goal

Reveille follows the Android language: the per-app language (Settings → Apps → Reveille → Language, Android 13+) when set, otherwise the system language. It ships English (default), Italian, Spanish, French and German. Dates, weekday names, numbers and the 12/24-hour clock follow the user's locale and settings.

## Non-goals

- No in-app language picker; no AppCompat.
- No translation of user-entered data (policy names, alarm labels).
- Log messages, exception text and release notes fetched from GitHub stay as they are.
- No right-to-left languages in this round (layouts aren't audited for RTL).

## Platform setup

- `app/build.gradle.kts`: `androidResources { generateLocaleConfig = true }`.
- `app/src/main/res/resources.properties`: `unqualifiedResLocale=en-US`.
- The generated `locales_config.xml` lists `en-US, it, es, fr, de`. On API 33+ the system shows the app in its per-app language list. On API 31–32 the app follows the system language.
- The per-app locale is stored by the system, not in our storage, so it is available in Direct Boot.

## Strings

- Every user-visible literal moves to `res/values/strings.xml`. Translations live in `values-it`, `values-es`, `values-fr`, `values-de`.
- Counts use `<plurals>`. Strings with arguments use positional args (`%1$s`, `%1$d`) so translators can reorder.
- Keys are grouped by prefix per area: `nav_`, `today_`, `policy_`, `oneoff_`, `health_`, `settings_`, `update_`, `ringing_`, `notif_`, `widget_`, `time_`.
- Compose code uses `stringResource` / `pluralStringResource`. Non-Compose code (`Notifier`, `RingingService`, `AlarmFiring`, `UpdateNotifier`, `UpdateInstaller`, the Glance widget) uses `context.getString` / `resources.getQuantityString`.
- Notification channel names and descriptions come from resources. `createNotificationChannel` runs again on each app start, so the names update after a language change.
- Content descriptions on icon-only buttons are translated too.
- Lint: `MissingTranslation` and `ExtraTranslation` are errors, so no locale can lack a key. `MissingQuantity` stays at its default.

### Text that is currently computed in non-UI code

- `ReliabilityChecker` builds check titles and explanations as English strings. Each check carries `@StringRes` ids and the UI resolves them. The data model holds no rendered text.
- `UpdateUiState`, `UpdateText` and `ReleaseNotes` do the same: state holds values, and the UI or notifier renders them.
- `PolicyValidation` returns error enums or ids, not messages.

## Engine (`:engine`) stays language-free

`:engine` has no Android dependency and cannot read resources. It returns values; the app renders them.

- `TimeText` is replaced by value types plus pure decision functions:
  - `DayLabel`: `Today`, `Tomorrow`, `Weekday(date)` (within 7 days), `Date(date)`. `dayHeader` and the day part of `dayAndTime` return it.
  - `Relative`: `Now`, `Minutes(n)`, `Hours(n)`, `Days(n)`, with the current rounding rules unchanged.
  - `DaySet`: `EveryDay`, `Weekdays` (Mon–Fri), `Custom(days)`.
- `ScheduleEngine.DEFAULT_ONE_OFF_LABEL` is replaced by `ScheduleSnapshot.defaultOneOffLabel: String = "Alarm"`. `ScheduleRepository` fills it from `R.string.oneoff_default_label` each time it builds a snapshot. Labels stay non-null, because `Armed.label` is persisted and shown by the ringing path. An unlabeled one-off's armed label is therefore in the language at arm time. Re-arming on a language change (below) refreshes it.
- The engine's tests keep covering the decisions (rounding, the 7-day boundary, the Mon–Fri detection). Text tests move to the app.

## App text layer

A new package `app/.../text/` holds the only place that turns values into text:

- `TimeFormats(locale, is24Hour)`, built with `TimeFormats.of(context)` (locale from the configuration, 12/24-hour from `DateFormat.is24HourFormat`):
  - `time(LocalTime)` follows the 12/24-hour setting. In 24-hour mode it returns `HH:mm`. In 12-hour mode it uses the locale's `getBestDateTimePattern(locale, "hmm")` (no forced leading zero).
  - `timeParts(LocalTime)` returns `(digits, period?)` for the large displays that render AM/PM smaller.
  - Dates use `DateFormat.getBestDateTimePattern(locale, skeleton)` with skeletons `EEEEdMMMM` (header and ringing screen), `EEEdMMM`, `dMMM` and `dMMMyyyy`.
  - Weekday names use `DayOfWeek.getDisplayName(style, locale)`. Day-letter chips use `NARROW` and the `FULL` name as content description. Repeated letters (English T/T, Italian M/M) are already the case today. The chips stay in fixed Monday-first order, so their position tells them apart.
  - `megabytes(bytes)` formats decimal megabytes with the locale's `NumberFormat`; the unit comes from `update_size_mb` (`%1$s MB`), since some languages abbreviate it differently.
  - Each pattern falls back to a fixed one if the locale's lookup throws, so formatting never throws on the alarm path.
- `Labels(res, formats)`, built with `Labels.of(context)`, renders `DayLabel`, `Relative`, `DaySet` and default labels through resources and plurals.
- In Compose, `ui/text/rememberLabels()` reads `LocalConfiguration`, so a locale or 12/24-hour change recomposes; screens reach the formats through `labels.formats`.
- `locale` always means `context.resources.configuration.locales[0]`, never `Locale.getDefault()`. With a per-app language those can differ in edge cases, so screens and notifications must use the same source.

All `Locale.ENGLISH` uses in `app/` and `engine/` go away, except for machine formats (ISO dates, file names, HTTP).

## 12-hour display

When the phone uses 12-hour time:

- Today hero, ringing screen and widget show `7:30` in the existing display style, followed by `AM` / `PM` at the label size and baseline-aligned.
- List rows and chips show `7:30 AM` in their normal style.
- `docs/design/README.md` gets a 12-hour note and token usage. One mockup (`Today`) gets a 12-hour variant via `renderVals()`.

## Runtime language and clock changes

- Activities recreate on a configuration change (the default). Compose screens read strings at composition time, so nothing is cached.
- `SystemEventsReceiver` also handles `ACTION_LOCALE_CHANGED` (system language; an exempt implicit broadcast). It re-arms through the existing path, which refreshes the persisted armed label and re-renders the widget. A per-app language change does not broadcast, but it recreates `MainActivity`, whose `onCreate` already re-arms ("app opened"). Re-arming is idempotent and keyed by occurrence, not label, so it never drops or duplicates an alarm. Both paths also call `WidgetUpdater.update` directly, because the re-arm only refreshes the widget when the armed alarm itself changed.
- `TIME_SET` already re-renders, which covers a 12/24-hour toggle.
- `SystemEventsReceiver` bounds its widget update to 5 s, so a slow Glance update can't hold `goAsync` until the broadcast ANRs.
- An already posted notification keeps its text until it is next updated.

## Alarm path safety

- No change to firing, claiming, re-arming or the fire log. Only string lookups change.
- Notifier calls made during a re-arm (missed alarm, fallback withdrawal, scheduling failed) are guarded: a failing notification is logged and can't abort the re-arm.
- Ringing and missed-alarm strings resolve from the device-protected context's resources (resources aren't encrypted storage). A Robolectric test resolves them from `createDeviceProtectedStorageContext()` under `@Config(sdk = [31, 33, 35])`.
- A missing translation can't crash the alarm path. Lint forbids it, and Android falls back to the default `values/` anyway.

## Layout

- German and French run about 30% longer than English. Buttons, chips, bottom-bar labels and the policy editor get checked on the emulator in `de`. Text either wraps (body) or ellipsizes (one-line labels with `maxLines = 1`). Touch targets stay at least 44 dp.
- The bottom-bar labels must fit in German ("Heute", "Zeitpläne", "Status", "Einstellungen"). German calls a policy "Zeitplan" (see the glossary), not "Richtlinie". If a label doesn't fit, it shrinks one type step at most. The design spec records the rule.

## Translations

- English is the source. Italian is reviewed by the owner. Spanish, French and German are drafted by the agent and marked for native review in the PR description.
- Terminology is kept consistent per locale via a short glossary in `docs/design/i18n.md`: alarm, policy, one-off, skip, snooze, dismiss, missed, Health.

## Testing

- Engine: unit tests for `DayLabel`, `Relative` and `DaySet` decisions (existing `TimeTextTest` cases are rewritten against the values).
- App (Robolectric):
  - `LabelsTest` and `TimeFormatsTest` run with `@Config(qualifiers = "en" | "it" | "de")`. They cover plurals, date order and 12- and 24-hour output.
  - The Direct Boot string-resolution test for ringing and missed notifications.
  - `ReliabilityChecker` tests assert ids, not English text.
- Lint: zero errors, including `MissingTranslation`.
- Maestro:
  - The existing flows assume the emulator is in `en-US` (the AVD default). `CLAUDE.md` states this.
  - Maestro can't run `adb`, so the locale flow goes through `scripts/maestro-i18n.sh`. The script runs `adb shell pm clear`, then `adb shell cmd locale set-app-locales com.replydev.reveille --locales it`, then `.maestro/i18n/italian.yaml`. The clear lives in the script because clearing app data also drops the per-app locale, so the flow launches without `clearState`. That subfolder isn't top-level, so plain `maestro test .maestro` skips it. The flow walks the four tabs asserting Italian labels and creates a one-off alarm. The script always resets the language to empty (follow the system) on exit.

## Known limitations

- The one-off editor's hour and minute entry boxes stay 24-hour input (`00`–`23`) even when the phone uses 12-hour time. The rest of the sheet and the result follow the setting.
- The policy editor's rule card shows the time as one `TimeFormats.time` string ("7:30 AM"), not through `TimeDisplay`, so AM/PM isn't set smaller there.

## Delivery

Every commit builds with all four checks green. Order:

1. `refactor(engine)` / `refactor(ui)` / `refactor(alarm)`: value types, the text layer, and strings externalized area by area. English only, no visible change.
2. `feat(ui)`: 12-hour display.
3. `feat(i18n)`: locale config plus the `it`/`es`/`fr`/`de` translations.
4. `test`/`docs`: the Italian Maestro flow and documentation.

The `feat` commits trigger a minor release.
